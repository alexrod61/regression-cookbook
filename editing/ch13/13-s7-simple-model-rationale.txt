# Revision rationale for the Simple Model section

## Scope
- Target chapter/file: book/13-generalized-poisson.qmd (branch Writing-for-Section-13).
- Exact section(s): NEW `## Simple Model: Satellite Counts and Female Crab Width {#sec-generalized-poisson-simple-model}` inserted between `## Estimation` and the draft-stale `## Goodness of Fit` (the latter is replaced in stage S8).
- Reference chapters/files reviewed: finished Ch10 simple-model section (fit-then-read order, tidied coefficient tables, terminology "expected-count ratio"); skill.md sections 2 (case-first), 12 (transitions), 14-16 (code/output conventions).

## What was preserved
- The draft's decision to fit the model with VGAM in R and with a custom statsmodels GenericLikelihoodModel in Python (the draft showed static previews; the fit is now executed on the canonical training split).

## What changed
- The section did not exist in the draft as executable content. Everything is executed at build time on `training_data` (86 crabs): VGAM `vglm(satellites ~ width_cm, genpoisson1(zero = "dispind"))` in R; the S6 `GeneralizedPoisson` class in Python.
- VGAM's raw dispersion row is decoded in chapter-visible code to theta_hat = 1 - exp(-exp(eta2)/2) with a delta-method standard error, because VGAM writes (1 - theta)^2 on a log-log link (empirically confirmed: eta2 = 0.372419 decodes to theta = 0.515976, matching Python's direct MLE).
- Tidied three-row coefficient tables per language (Intercept, width_cm, Dispersion theta) with Wald z and p columns; R table printed with print_as_dt, Python via scrollable_table_html + hidden R chunk (the pattern established in S3).
- Reading-the-estimates prose uses terminology "expected-count ratio" (never "IRR"), gives the 25.7% figure with its exponentiated 95% CI (1.154, 1.370), decodes theta_hat into a variance multiplier (4.27x), and flags the intercept as calibration-only.
- Added the training-set-significance Heads-up: p-values here are model-checking signals; the inferential claim waits for the Results refit (consistent with the book's workflow).
- Parity sentence is itself executed inline (`r` reading both logLik values, including the Python object through reticulate), so the claim cannot drift from the code.

## Why the changes help
- Estimation moves from a static promise to executed, verified output; the draft only previewed code and never knitted numbers.
- The decoding of VGAM's two-intercept output is a real comprehension barrier for students; making it explicit code with comments removes a recurring source of confusion AND documents the genpoisson1 parameterization choice, which differs from the appendix's notation.
- Cross-language parity (logLik -177.7141 vs -177.71414, identical betas, sum of fitted means 245 = sum of y in both) is now a demonstrated property, not an assertion.
