## Exploratory Data Analysis {#sec-generalized-poisson-eda}

With the data wrangled, we move to **exploratory data analysis** (as shown in @fig-ds-workflow-eda). The goal is to describe the data before modelling them: How are the satellite counts distributed? Is there descriptive evidence of overdispersion? Which regressors appear to be related to the response? Per the data science workflow, all EDA uses the **training data only**, so we first create the training/testing split.

We use the same canonical split as @sec-classical-poisson — a 50/50 simple random split with seed 123 — so that the training observations analysed in this chapter are exactly those analysed in the Classical Poisson chapter:

- @lst-generalized-poisson-data-splitting-r uses the [{rsample}](https://rsample.tidymodels.org/) package to split the wrangled `crabs` dataset into training and testing sets. The argument `prop = 0.5` requests that approximately half of the observations be assigned to the training set, with the rest assigned to the testing set. The sanity check prints the dimensions of both subsets and their observed proportion.
- In `Python`, we do not re-split the data. Per the book's cross-language convention, the `R`-generated split is the canonical one, and the next listing shows how the `Python` analysis imports it.

::: {.panel-tabset}

## **`R`**

```{r}
#| echo: true
#| lst-label: lst-generalized-poisson-data-splitting-r
#| lst-cap: "Code to randomly split the horseshoe crab data into training and testing sets."
#| message: false
#| warning: false
# Setting the seed for reproducible splitting
set.seed(123)

# Performing the 50/50 training/testing split
split <- initial_split(crabs, prop = 0.5)
training_data <- training(split)
testing_data <- testing(split)

# Sanity checks: dimensions and proportions
n_total <- nrow(crabs)
n_train <- nrow(training_data)
n_test  <- nrow(testing_data)

cat("Total observations:", n_total, "\n")
cat("Training observations:", n_train,
    "(", round(100 * n_train / n_total, 1), "%)\n")
cat("Testing observations:", n_test,
    "(", round(100 * n_test / n_total, 1), "%)\n")
```

:::

::: {.Tip}
:::: {.Tip-header}
Tip on the 50/50 split and more careful alternatives!
::::
:::: {.Tip-container}
This dataset contains only `r n_total` observations. A standard predictive modelling workflow often uses a larger training set, such as an 80/20 training/testing split. However, in this chapter we need to support two goals at the same time: an **inferential** inquiry and a **predictive** inquiry.

Using a 50/50 split is a compromise. It gives the training set enough observations for EDA, model fitting, and goodness-of-fit checking, while also leaving a testing set large enough to support both the final **predictive accuracy assessment** and the final **inferential refit**. This choice is not perfect. A larger training set would usually help estimation and diagnostics, while a larger testing set gives a more informative final assessment. With small datasets, we often have to choose between these inconveniences.

The 50/50 split used here is also a **simple random split**, which means it does not explicitly protect against imbalance across important variables. For example, if one female crab colour category or spine condition is rare, a simple random split could place too many of those crabs in one subset and too few in the other. That imbalance can affect both the inferential and predictive parts of the workflow.

A more careful split could stratify the data by an important categorical regressor, such as female crab colour, or by a coarser grouping of the response variable. Other strategies include repeated random splits, cross-validation, or bootstrap-based assessment. These approaches can reduce dependence on a single split and are widely used in predictive modelling and model validation; see @hastie2009, @kuhn2013, and @harrell2015 for broader discussions. The main chapter keeps a single 50/50 split so that the Generalized Poisson regression workflow remains transparent, and so that the results remain directly comparable with @sec-classical-poisson.
::::
:::

::: {.Heads-up}
:::: {.Heads-up-header}
Heads-up on keeping R and Python aligned after the split!
::::
:::: {.Heads-up-container}
Setting the same seed in `R` and `Python` does **not** guarantee the same observations in each subset: the two languages use different random-number generators and different splitting implementations. To keep genuine `R`/`Python` parity, we use the `R`-generated training and testing sets as a common reference. The listing below imports them into `Python` through the [{reticulate}](https://rstudio.github.io/reticulate/) package and restores the categorical data types and level ordering that the transfer would otherwise lose.
::::
:::

::: {.panel-tabset}

## **`Python`**

```{python}
#| echo: true
#| lst-label: lst-generalized-poisson-import-r-split-py
#| lst-cap: "Code to import the R-generated training and testing sets into Python."
#| message: false
# Importing R-generated training and testing sets via reticulate
training_data = r.training_data
testing_data = r.testing_data

# Ensuring categorical regressors are treated as categorical in Python
color_levels = ["Light", "Medium light", "Medium dark", "Dark"]
spine_levels = ["Both good", "One worn or broken", "Both worn or broken"]

training_data["color"] = pd.Categorical(
    training_data["color"], categories=color_levels, ordered=True
)
training_data["spine"] = pd.Categorical(
    training_data["spine"], categories=spine_levels, ordered=True
)
testing_data["color"] = pd.Categorical(
    testing_data["color"], categories=color_levels, ordered=True
)
testing_data["spine"] = pd.Categorical(
    testing_data["spine"], categories=spine_levels, ordered=True
)

# Sanity checks: sample sizes, and disjointness of the two splits
n_total_py = len(r.crabs)
print("Total observations:", n_total_py)
print("Training observations:", len(training_data))
print("Testing observations:", len(testing_data))
print(
    "Training + testing equals total:",
    len(training_data) + len(testing_data) == n_total_py,
)
```

Three features stand out in the training data. First, the distribution is **right-skewed**, with many small counts and a few nests with many satellites. Second, `r sum(training_data$satellites == 0)` of the `r n_train` training crabs (about `r round(100 * sum(training_data$satellites == 0) / n_train)`%) have **zero satellites**, so the zero category is prominent. Third — and most important for this chapter — the sample variance (`r round(var(training_data$satellites), 2)`) is more than three times the sample mean (`r round(mean(training_data$satellites), 2)`), giving a variance-to-mean ratio of about `r round(var(training_data$satellites) / mean(training_data$satellites), 2)`.

::: {.Heads-up}
:::: {.Heads-up-header}
Heads-up on reading dispersion from raw summaries!
::::
:::: {.Heads-up-container}
The variance-to-mean ratio computed here is a **marginal** summary: it ignores the regressors completely. A ratio far from one is an early warning, not a verdict. Equidispersion is a **conditional** assumption about the distribution of $Y_i$ given the regressors included in the model. The training-stage dispersion diagnostics in @sec-generalized-poisson-gof are what actually check that assumption.

At the same time, a marginal ratio of `r round(var(training_data$satellites) / mean(training_data$satellites), 2)` is large enough that the Generalized Poisson model — explicitly designed for such departures — is the natural model to develop.
::::
:::

### Satellite Counts and Continuous Regressors {#sec-generalized-poisson-eda-continuous}

Next, is the response related to the two continuous regressors? Because counts are noisy, we follow the same device as @sec-classical-poisson: split each continuous regressor into intervals, compute the average satellite count per interval, and overlay those averages on the scatterplot. These binned averages are a **descriptive visual guide**, not the fitted regression model.

@fig-generalized-poisson-eda-width-r and @fig-generalized-poisson-eda-width-py show the relationship with `width_cm`; the pattern is an approximately monotone increase in the average satellite count as shell width grows.

::: {.panel-tabset}

## **`R`**

```{r}

  mutate(width_bin = cut(width_cm, breaks = n_intervals)) |>
```

### Satellite Counts and Categorical Regressors {#sec-generalized-poisson-eda-categorical}

For the categorical regressors, @tbl-generalized-poisson-eda-categorical-r and @tbl-generalized-poisson-eda-categorical-py report group sizes, group means, and group variances of the satellite counts for each colour category and each spine condition in the training data. Two observations will matter later: the group means vary across colour categories in the expected direction (darker females attract fewer satellites), and within **every** group the sample variance remains well above the sample mean — descriptive evidence that the overdispersion is not explained away by any single regressor.

### Summary {#sec-generalized-poisson-eda-summary}

@tbl-generalized-poisson-eda-summary summarizes the exploratory findings and what they imply for the modelling stage.

| **Feature investigated** | **Descriptive evidence (training data)** | **Implication for modelling** | **Caution** |
|:---|:---|:---|:---|
| Response distribution | Right-skewed counts; 34 of 86 crabs have zero satellites; range 0 to 12. | A count model with a positive expected count is required; the log link is appropriate. | Marginal summaries ignore the regressors. |
| Mean–variance relationship | Variance-to-mean ratio of about 3.37; group variances exceed group means within every colour and spine group. | Equidispersion is implausible; a model with an explicit dispersion parameter, such as the Generalized Poisson, is motivated. | The formal checks happen in goodness of fit, on the fitted conditional model. |
| `width_cm` | Interval-average satellite counts increase with shell width. | Width is the natural first regressor for the simple model. | Binned averages are descriptive, not the fitted mean function. |
| `weight_kg` | Interval averages also increase, but the heaviest intervals contain very few crabs. | Weight is a candidate for the extended model. | Sparse high-weight intervals make the right-hand pattern imprecise. |
| `color`, `spine` | Group means differ modestly; `Light` has only 8 training crabs and `One worn or broken` only 7. | Colour and spine remain candidate regressors with explicit reference categories. | Small groups produce imprecise contrasts; no rebalancing is done. |

: EDA summary for the horseshoe crab training data. {#tbl-generalized-poisson-eda-summary .striped .hover}

The exploratory evidence points in one consistent direction: the training counts are strongly overdispersed, even within regressor-defined groups, while the expected count clearly varies with female crab size. The next section turns these descriptive observations into a formal probability model: the Generalized Poisson regression model.
